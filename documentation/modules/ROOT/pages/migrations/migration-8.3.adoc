= 8.3 Migration Guide

:toc-title:

:product-version-changelog: https://github.com/axelor/axelor-open-platform/blob/8.3/CHANGELOG.md

In this document, we will see the major steps to migrate from 8.2 to 8.3.

NOTE: Please check the https://github.com/axelor/axelor-open-platform/blob/8.3/CHANGELOG.md[changelog] for a detailed
list of fixes, changes, and improvements introduced in 8.3.

== Client IP address read from a single header

The client IP address, ie what `getRemoteAddr()` returns behind the proxy filter, is now the left-most address of a
single header: the header configured with the new `application.client-ip-header` setting, such as `X-Real-IP`, or
`X-Forwarded-For` if none is configured. That address is validated and normalized, ie any port suffix is stripped and
IPv6 addresses are canonicalized, whereas the left-most `X-Forwarded-For` value was previously used as it is.

If that header is missing, or doesn't provide a valid IP address, the address of the direct connection is used. There
is no fallback to other headers, as the reverse proxy may not overwrite them, so they may have been forged by the
client.

This header is trusted as it is, so the reverse proxy must overwrite it, and the application must only be reachable
through the proxy.

WARNING: Previous versions of this guide recommended `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`
for nginx. This keeps the `X-Forwarded-For` value sent by the client, whose left-most address would then be used as the
client address. Update the nginx configuration:

[source,nginx]
----
proxy_set_header X-Forwarded-For $remote_addr;
----

See xref:dev-guide:application/config.adoc#client-ip-address[Client IP address] for the full requirements, including
deployments without a reverse proxy or behind a CDN.

== Record user authentications

Successful interactive logins are now recorded as `AuthenticationEvent` records: sign-in with the login form (local
or LDAP), indirect basic authentication and single sign-on providers (OpenID Connect, OAuth, SAML, CAS…). Each event
stores the user, a human-readable provider name, the IP address, the date, and some details such as the second factor
used and the user agent. See xref:dev-guide:modules/security.adoc#authentication-events[Authentication Events] for more
details.

Users other than administrators need a read permission on `com.axelor.auth.db.AuthenticationEvent` to see their own
history, and they will only ever see their own events.

A new `auth_authentication_event` table is required. See the <<Full migration script>> below.

Authentication events are kept for 180 days, then deleted by the new `authentication.events.purge` scheduled job,
which runs every day. The retention period can be changed with the `auth.events.retention`
setting.

This scheduled job is only created on new databases. On an existing database, create it from
menu:Administration[Job Management > All Schedules], with:

* *Name*: `authentication.events.purge`
* *Description*: `Delete older authentication events`
* *Job*: `com.axelor.auth.events.job.AuthenticationEventPurgeJob`
* *Cron*: `0 0 5 * * ?` (every day at 5 AM)
* *Active*: checked

or run the following SQL script :

[source,sql]
----
INSERT INTO meta_schedule (id, version, created_on, active, cron, description, job, name)
VALUES (nextval('auth_authentication_event_seq'), 0, now(), true, '0 0 5 * * ?',
        'Delete older authentication events','com.axelor.auth.events.job.AuthenticationEventPurgeJob',
        'authentication.events.purge');
----

== Full migration script

Here is the full SQL migration script for all built-in AOP entities :

[source,sql]
----
create table auth_authentication_event
(
    id         bigint  not null primary key,
    archived   boolean,
    version    integer,
    created_on timestamp(6),
    details    jsonb,
    ip_address varchar(255),
    provider   varchar(255),
    status     integer not null,
    user_id    bigint constraint fk_fcd7fnyrr3qavk2xuco4ov3d8 references auth_user
);

create index auth_event_idx_user on auth_authentication_event (user_id, created_on);
create index auth_event_idx_created_on on auth_authentication_event (created_on);
create index auth_authentication_event_user_id_idx on auth_authentication_event (user_id);

INSERT INTO meta_schedule (id, version, created_on, active, cron, description, job, name)
VALUES (nextval('auth_authentication_event_seq'), 0, now(), true, '0 0 5 * * ?',
        'Delete older authentication events','com.axelor.auth.events.job.AuthenticationEventPurgeJob',
        'authentication.events.purge');
----
